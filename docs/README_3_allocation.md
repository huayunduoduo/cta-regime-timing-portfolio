# 股债金改进研究版：先运行 portfolio_research.py

本版已经实际运行，不是待实施计划。保留原AR-GARCH研报复现和状态改造，新增多资产账本、36组对照、年度滚动选择、ES限仓和VaR/ES诊断。

## 我建议先用哪一版

**后续验证主方案：股债金月度逆波动配置 `benchmark_invvol_monthly`。**

这是资产配置方案，不能说研报CTA已复现成功。它在本轮中以较低复杂度获得较好的收益/回撤平衡；没有对全部可能策略找到数学上的最优解。这个推荐已参考本轮历史结果，今后应冻结规则再检验新数据。

2020-01-01至2025-12-31，按252交易日年化，全部按每次成交佣金1‰、滑点1‰扣费：

| 组合 | 年化收益 | 最大回撤 | 卡玛比 |
|---|---:|---:|---:|
| 原多空CTA，各1/3初始资金 | -2.28% | -27.78% | -0.082 |
| no_rho_3多头CTA，各1/3初始资金 | 3.33% | -10.74% | 0.310 |
| **月度逆波动配置（主方案）** | **7.50%** | **-4.83%** | **1.552** |
| 年度滚动前三组合 | 7.64% | -5.00% | 1.526 |
| 2019年底固定前三组合 | 7.64% | -5.00% | 1.526 |
| 月度等权配置 | 9.14% | -11.69% | 0.782 |

等权配置历史收益更高，也承担更大回撤；滚动前三的额外复杂度没有带来明显优势。这些组合与单个ETF的14%/20%年化不是相同风险暴露，不能直接拿收益高低判断信号优劣。

主方案2022年仍亏损约0.58%，2020—2022年化约3.31%，2023—2025约11.88%。并非每年都能赚7.50%。双倍成本年化约7.33%。

## Windows / VS Code：一步步运行

1. **新解压到一个新文件夹**，例如 `D:/cta/cta_paper_daily_new`。不要把Python代码和终端命令混在一起。用VS Code“文件 → 打开文件夹”打开包含本README和portfolio_research.py的文件夹。
2. 仓库不随包分发行情数据，需自备 `data/etf_daily.csv`、`data/etf_dividend.csv`（字段格式见 [DATA.md](../DATA.md)），不需要改字段或另存 Excel。
3. 你已有cta_research环境。在VS Code底部终端逐行输入（PowerShell）：

```powershell
conda activate cta_research
cd D:\cta\cta_paper_daily_new
python -m pip install -r requirements.txt
python portfolio_research.py --data data
```

`cd`后面的路径要改成你自己解压后的实际路径。如果终端已经在项目文件夹中，就不需要再输入cd。

4. 成功后会打印HTML路径。打开 `results/portfolio/portfolio_report.html`。本包已经有生成好的报告，可以先双击阅读。
5. 新入口不依赖AR-GARCH缓存，不调用C++，无需安装g++。不需要重跑1000次Bootstrap。已有数据下本地完成约几十秒；机器速度不同会有差异。
6. 若想只检查新增账本，运行：

```powershell
python -m unittest discover -s tests -p test_portfolio.py -v
```

若提示找不到Python或numpy，请在VS Code用 `Ctrl+Shift+P → Python: Select Interpreter` 选择cta_research，再新建终端。

原状态改造入口仍然可用：

```powershell
python run_improvements.py --data data
python build_improvements_report.py
```

它生成的是 `results/improvements/improvements_report.html`，与新组合报告分开。本版也修复了该入口的Windows换行哈希问题，以及较新版pandas下 `output array is read-only` 的问题。**不要手动改cache文件名。**

## 主方案到底怎么做

- 仅交易510300沪深300ETF、518880黄金ETF、511010国债ETF；只做多，不加杠杆。
- 每月首个已经观察到的交易日收盘，用截至该收盘的最近60日复权收益标准差计算波动率。
- 基础权重与波动率成反比，归一化后对单个ETF设60%目标上限，超出的部分按比例分给其余ETF。
- 下一交易日开盘按未复权价格成交。先卖后买、扣费、限制可用现金；调仓之间权重自然漂移。
- 该主方案不需要识别趋势，不强加RSI、ATR止损或ES开关；这些在对照中检验，没有观察到稳定优势。
- 本轮平均实际权重约17.3%股票、22.8%黄金、59.9%国债。低回撤主要对应更低权益暴露与分散配置，并不证明存在很强的择时能力。
- 初始资金1单位、小数份额，不计最低佣金和整手约束。实盘需要按资金规模另做整手成交，不能直接把小数数量当下单指令。

## 改进思路及已实现增量
1. 从“收益自相关一定为正才交易”转向直接比较慢速价格趋势；避免只靠放松统计门槛追逐历史收益。
2. 在单资产CTA之外建立真实股债金配置账本。等权、逆波动、协方差风险平价；各自都对照，保留简单基准。
3. 周/月低频调仓减少摩擦；账本保留实际持仓漂移、现金、股息应收和逐笔成交。
4. 一日97.5%历史ES用过去252日联合资产冲击；预算为组合净值1.5%时缩放目标仓位。它限制估计风险，不保证实际损失上限。
5. ES与同规则无ES、固定降仓比例比较；降仓比例只用2015—2019估计。本轮三均线逆波动组合ES未产生实际差异，不能称其改善收益。
6. 一日风险预测包含历史模拟、EWMA正态、过滤历史模拟，输出超限率与连续超限情况。没有将接近理论超限率写成统计校准成功。
7. 逐日收益归因分解为各ETF价格贡献、除息股息、交易成本；核对贡献总和等于净值变化。

**未实现宏观择时。** 当前没有增长/流动性数据及其真实发布日期序列，不用事后修订值制造宏观增量。报告中不会把未来计划当已完成结果。

## 如何控制选参偏差

- 统一候选：3种趋势（无、MA120、MA60/120/240分档）×3种配置（等权、逆波动、风险平价）×2种调仓（周/月）×2种ES（关/1.5%）=36个。
- 学习期2015—2019；另列2020—2022及2023—2025阶段。所有候选和失败结果输出，不按不同ETF分别挑历史最高收益版本。
- 固定评分：CAGR / max(6%, |最大回撤|) − 0.02×年化单边换手。分母下限避免靠几乎全现金取得虚高分数。
- 固定前三只用2019年底前的数据；年度滚动前三每年只用截至上年底的数据。相同基础规则的ES开关不能同时占两个席位。
- 组合在年间连续运作，不重置净值或仓位；新成员在上一年最后交易日收盘形成目标，下一年首个交易日开盘成交。
- 2020—2025在此前研究已被看过，**这些不是全新未触碰样本外**。选参机制虽只用过去信息，研究设计仍存在历史反馈；今后新数据才有更强验证价值。
- `deployment.json`给出截至末日选出的下期三个成员，也记录主方案。它们的回溯结果不能再算独立验证。

## 以后追加新数据

保留CSV字段和历史数据，只追加真实新行情/分红；三个ETF的交易日必须一致。运行时明确新终点，例如：

```powershell
python portfolio_research.py --data data --end 2026-05-29 --out results/portfolio_20260529
```

这条命令只是示例；当前包不含2026行情，未补齐前运行会明确报错。新组合入口每次从数据重算，速度较快；没有增量缓存导致旧结果混入的风险。原AR-GARCH缓存只对应旧输入，更新数据后若重跑原模型需另行重估。

## 验证与环境边界

本地Linux/Python3.12环境实际通过26项测试（含原模型测试），新组合会计贡献核对最大误差低于1e-12。测试覆盖下一开盘成交、股息确认/支付、应收不能融资、费用、卖出优先、未来价格不改过去信号、历史排序不受未来净值影响。新增入口不需要C++，但全套原模型测试和模型重估需要g++；没有声称已在你的Windows机器上实际运行。

原研报规则见 [RULES.md](../RULES.md)，旧版运行说明见 [README_windows_quickstart.md](README_windows_quickstart.md)；新组合规则以本文与portfolio_research.py为准。
